# Proposal

## Why

目前客戶主檔視圖（http://localhost:8080/customer）在新增與修改客戶時，客戶編號仍提供使用者手動輸入或留空，缺乏與員工及產品模組一致的自動編號與防呆機制；視圖模組與表單彈窗未完整呈現資料庫中的所有欄位（如電子郵件未於列表呈現、國家欄位在彈窗中被寫死而無輸入介面等）；且當新增或修改客戶發生資料重複（如電話、統一編號、電子郵件、客戶編號）時，未明確告知使用者是哪一項欄位重複且缺乏問題欄位聚焦導引。為提升系統資料一致性、健全主檔防呆與優化操作體驗，需對客戶主檔模組進行全面優化。

## What Changes

- **任務 1：資料庫所有欄位於視圖模組完整呈現（排除修改時間，同步於新增與修改客戶）**：
  - 資料庫 `customer` 資料表包含 13 個欄位：`customer_id`、`customer_name`、`phone`、`email`、`company_name`、`tax_id`、`country`、`city`、`district`、`address`、`employee_id`、`created_at`、`updated_at`。
  - **資料表格**：完整呈現除 `updated_at`（修改時間）之外的所有欄位，包括客戶編號、客戶姓名、聯絡電話、電子郵件、公司抬頭、統一編號、國家、城市與區域、詳細地址、專屬業務窗口（員工姓名與編號）、建立時間。
  - **彈窗表單（新增與修改客戶同步）**：表單完整對應資料庫欄位（排除修改時間），補齊「國家」（預設為「台灣」）輸入/選擇欄位；負責員工改為下拉式選單（動態加載員工主檔清單）。
- **任務 2：新增客戶與修改客戶時明確告知重複欄位**：
  - **後端重複性檢驗**：新增與修改客戶時，針對「客戶編號」、「聯絡電話」、「統一編號」（若有填寫）及「電子郵件」（若有填寫）進行唯一性檢核（修改時排除自身）。若檢測到重複，拋出明確 HTTP 400 錯誤訊息（例如：「客戶電話已存在: [電話]」、「客戶統一編號已存在: [統編]」、「客戶電子郵件已存在: [信箱]」、「客戶編號已存在: [編號]」），絕不產生 HTTP 500 內部伺服器錯誤。
  - **前端錯誤提示與欄位聚焦**：當表單送出遭遇重複或格式錯誤時，跳出 Alert 明確告知重複或錯誤項目，並自動聚焦（focus）與高亮標記該輸入欄位。
- **任務 3：客戶編號由系統配置，不提供使用者輸入**：
  - **前端表單**：新增客戶表單中客戶編號輸入框設為禁用（disabled）並標註「由系統自動配置」；修改客戶時客戶編號維持唯讀鎖定。
  - **後端自動編號**：新增客戶時由後端依據當前年月（例如 `202609`）及流水號（例如 `202609001`）自動生成不重複之客戶編號，不接受或覆寫使用者手動傳入之客戶編號。

### Modified Capabilities
- `mofei-erp-master-data`: 更新客戶主檔 CRUD 規範（客戶編號由系統自動配置不提供使用者輸入、資料庫所有欄位完整呈現排除修改時間、重複欄位明確提示檢核）。

## Impact

- **後端程式碼**：
  - `CustomerDTO.java`: 完善各欄位驗證與 DTO 定義。
  - `CustomerServiceImpl.java`: 實作客戶編號自動配置流水號；新增與修改客戶時針對客戶電話、統一編號、電子郵件實施重複檢核並拋出明確例外；負責員工下拉關聯檢驗。
  - `GlobalExceptionHandler.java`: 擴充 `FIELD_NAME_MAP` 補齊客戶相關欄位（taxId、companyName、country、city、district、address），確保驗證例外轉換訊息精確易懂。
- **前端視圖與腳本**：
  - `templates/customer.html`: 調整表格欄位完整呈現（新增電子郵件、國家等，排除修改時間）；彈窗補齊國家欄位，客戶編號禁用/唯讀，負責員工改為下拉選單；實作重複欄位精確錯誤訊息與高亮聚焦功能。
- **測試案例**：
  - `MasterDataApiTest.java`: 新增客戶編號自動配置、客戶電話重複檢核、統一編號重複檢核、電子郵件重複檢核、修改時排除自身重複等測試案例。
